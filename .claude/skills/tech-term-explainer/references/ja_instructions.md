# tech-term-explainer — 日本語詳細説明

このファイルは `SKILL.md` の補足です。スキルの動作・設計意図・設定方法を日本語で詳しく説明します。

---

## スキルの目的

指定された技術用語を **事実に基づいてのみ** 解説し、Markdown ファイルとして保存するスキルです。

### コスト削減の設計

- **SKILL.md を英語で記述**: 英語はトークン効率が高く、毎回の読み込みコストを下げます。
- **Haiku モデルをサブエージェントに使用**: 解説生成は軽量な Haiku モデルに委ねることで、Sonnet / Opus の使用を最小化します。
- **詳細説明（このファイル）を分離**: 詳細な日本語説明はサブディレクトリに置き、必要なときだけ参照します。SKILL.md 本体は簡潔に保ちます。

---

## 出力ファイルの仕様

### ファイル名規則

技術用語をスネークケースに変換してファイル名にします。

| 入力用語 | ファイル名 |
|---------|-----------|
| WebSocket | `web_socket.md` |
| Docker | `docker.md` |
| GraphQL | `graph_ql.md` |
| REST API | `rest_api.md` |
| CI/CD | `ci_cd.md` |

### 出力先ディレクトリの決定ロジック

```
CLAUDE.md に tech_term_output の設定あり
    → その値のディレクトリに保存
CLAUDE.md はあるが tech_term_output の設定なし
    → CLAUDE.md と同じディレクトリ（プロジェクトルート）に保存
CLAUDE.md が見つからない
    → カレントディレクトリに保存
```

### CLAUDE.md への設定例

プロジェクトの `CLAUDE.md` に以下を追加することで、出力先を固定できます。

```markdown
## tech-term-explainer
tech_term_output: docs/terms/
```

この設定がある場合、解説ファイルは `docs/terms/web_socket.md` のように保存されます。

## 解説の品質基準

### ✅ 含めるもの

- 公式ドキュメント・仕様書・広く認められた技術書に基づく説明
- 動作原理（どのように機能するか）
- 実際のユースケース（どの場面で使われるか）
- 関連技術との比較・位置づけ
- 調査中に実際に参照した URL（「参照ソース」セクション）

### ❌ 含めないもの

- 「〜と思われる」「〜かもしれない」「〜でしょう」などの推測表現
- 将来の動向・予測・ロードマップ（公式発表がない場合）
- 個人的な評価・推薦（「〜が優れている」など主観的な表現）
- 情報が不確かな場合は「情報不足のため記載なし」と明記する

## 参照ソースの記録について

解説を生成する際に実際にアクセスした URL は、すべて **「参照ソース」セクション** に記録します。これはいわゆる一時ソース（primary/temporary sources）の記録です。

### 目的

- 情報の出典を明確にし、後から検証できるようにする
- 時間が経っても「どこから得た情報か」を追跡できる
- 推測ではなく調査に基づく解説であることを示す

### ルール

| 状況 | 記載内容 |
|------|----------|
| URL を実際に取得・参照した | 参照した URL を Markdown リンク形式で列挙 |
| URL を参照しなかった（学習データのみ） | `なし（学習データのみ使用）` と明記 |

### 記載形式

```markdown
### 参照ソース
- [MDN Web Docs — WebSocket](https://developer.mozilla.org/ja/docs/Web/API/WebSocket)
- [RFC 6455 — The WebSocket Protocol](https://www.rfc-editor.org/rfc/rfc6455)
- [Docker 公式ドキュメント](https://docs.docker.com/get-started/overview/)
```

または参照なしの場合：

```markdown
### 参照ソース
なし（学習データのみ使用）
```

### 重要な注意

- 実際にアクセスした URL **のみ** を記録する。アクセスしていない URL を推測で記載しない。
- リンク先のタイトルは正確に記す（アクセスして確認できた場合）。
- アクセスできなかった URL（エラー等）は記載しない。

## トークン使用記録について

解説ファイルの末尾には、以下の形式でトークン使用量を記録します。

```
---
📊 **トークン使用記録**
- モデル: claude-haiku-4-5-20251001
- トークン合計: 1,247
- 実行時間: 3,241 ms
```

この情報はサブエージェントのタスク完了通知（`total_tokens`・`duration_ms`）から取得します。
コスト管理・最適化の参考として活用してください。

## 複数用語の同時解説

複数の技術用語を一度に解説する場合は、**用語ごとに別ファイルを作成**します。

例: 「WebSocket と SSE の違いを教えて」と聞かれた場合
- `web_socket.md` を作成
- `sse.md` を作成
- それぞれのファイルにトークン使用記録を記載

## 出力例

```markdown
## WebSocket

### 概要
WebSocket は、クライアントとサーバー間で全二重通信を可能にするプロトコルである。
HTTP のリクエスト・レスポンスモデルとは異なり、一度接続を確立すると双方向にデータを
リアルタイムで送受信できる。RFC 6455 で標準化されている。

### 仕組み・動作原理
HTTP アップグレードリクエスト（`Upgrade: websocket` ヘッダー）を使ってハンドシェイクを行い、
TCP 接続をそのまま保持してメッセージをフレーム単位で交換する。
クライアント送信フレームはマスキング処理が必須。バイナリとテキストの両フレームタイプをサポート。

### 主な用途・ユースケース
- リアルタイムチャットアプリケーション
- 株価・為替レートのライブ配信
- オンラインゲームの状態同期
- 協調編集ツール（Google Docs 型）
- 監視ダッシュボードのリアルタイム更新

### 関連技術・概念
- **SSE（Server-Sent Events）**: サーバー→クライアント単方向のストリーミング。WebSocket より実装が簡単。
- **HTTP/2 Server Push**: HTTP/2 の仕組みを使ったプッシュ配信。双方向ではない。
- **Socket.IO**: WebSocket を抽象化したライブラリ。自動フォールバック機能を持つ。
- **MQTT**: IoT 向けの軽量メッセージングプロトコル。

### 参照ソース
- [MDN Web Docs — WebSocket API](https://developer.mozilla.org/ja/docs/Web/API/WebSocket)
- [RFC 6455 — The WebSocket Protocol](https://www.rfc-editor.org/rfc/rfc6455)

---
📊 **トークン使用記録**
- モデル: claude-haiku-4-5-20251001
- トークン合計: 1,247
- 実行時間: 3,241 ms
```
